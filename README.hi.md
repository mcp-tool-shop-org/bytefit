**हार्डवेयर-जागरूक स्थानीय-एलएलएम लोडआउट योजनाकार।** यह आपको बताता है कि आपका मशीन वास्तव में सबसे बड़ा, सबसे सक्षम मॉडल कौन सा चला सकता है — सटीक क्वांटाइजेशन, केवी-कैश, संदर्भ लंबाई और ऑफलोड नीति के साथ — और उन कॉन्फ़िगरेशनों को अस्वीकार करता है जो चुपचाप डिस्क पर पेजिंग करेंगे।

बाइटफिट एक **सलाहकार** है, केवल एक अनुमानक नहीं। जेन और एलएम स्टूडियो आपको बताते हैं कि क्या कोई मॉडल *फिट* बैठता है; बाइटफिट आपको बताता है कि क्या *चलाना* है — मॉडल क्लास + क्वांट + केवी-कैश प्रकार + संदर्भ + ऑफलोड नीति — और किसी भी ऐसे कॉन्फ़िगरेशन को **अस्वीकार** करता है जो अनियंत्रित पेजिंग में बदल जाएगा (जिससे डिकोड थ्रूपुट लगभग 78 गुना कम हो जाता है)।

```
decode tok/s  ≈  memory_bandwidth ÷ bytes-read-per-token
```

डिकोड मेमोरी-बैंडविड्थ-सीमित है। बाइटफिट प्रति-टोकन पढ़े गए बाइट्स को कम करता है, उन्हें सबसे तेज़ स्तर पर रखता है जो फिट बैठता है, परिणाम की भविष्यवाणी करता है, और उन कॉन्फ़िगरेशनों को अस्वीकार करता है जो पेजिंग करेंगे।

## त्वरित शुरुआत

```bash
npm install -g @mcptoolshop/bytefit

bytefit probe                # what hardware you have
bytefit recommend            # rank your installed Ollama models, best-first
bytefit plan qwen3.6:27b     # a full loadout + ready-to-run llama.cpp / Ollama args
```

## यह क्या करता है

- **जांच** — वीआरएएम, रैम और एनवीडिया, एएमडी और ऐप्पल सिलिकॉन में *मापी गई* एनवीएमई बैंडविड्थ।
- **चुनें** — मॉडल क्लास, क्वांट परिवार, केवी-कैश प्रकार, संदर्भ लंबाई और आपके हार्डवेयर के लिए ऑफलोड नीति।
- **अस्वीकार** — उन कॉन्फ़िगरेशनों को जो चुपचाप डिस्क पर पेजिंग करेंगे, एक संरचित कारण और गैर-शून्य एग्जिट कोड के साथ।
- **उत्पन्न करें** — चलाने के लिए तैयार लामा.cpp / ओलामा / एलएम स्टूडियो तर्क और एक अनुमानित टोक/एस।

यह आपके स्थापित **ओलामा** मॉडल को तुरंत रैंक करता है, `.gguf` फ़ाइलों की एक फ़ोल्डर को स्कैन करता है (`--dir`), या डाउनलोड किए बिना एक **हगिंग फेस** जीजीयूएफ रिपॉजिटरी को रैंक करता है (`--hf <repo>`)।

## क्यों

फिट लेबल और मेमोरी अनुमान बुनियादी आवश्यकताएं हैं। कोई भी मौजूदा उपकरण *निर्णय* चक्र को पूरा नहीं करता है: हार्डवेयर-फिंगरप्रिंटेड क्वांट + केवी-प्रकार अनुशंसा, क्वांट-समायोजित हेडरूम से जुड़ी संदर्भ आकार, एक मॉडल-क्लास अनुशंसा और एक कठोर एंटी-पेजिंग अस्वीकृति। यह संयोजन बाइटफिट है। आर्किटेक्चर और प्रत्येक हेयुरिस्टिक के पीछे का प्रमाण [SPEC.md](SPEC.md) और [docs/research-grounding.md](docs/research-grounding.md) में है।

## आवश्यकताएं

नोड ≥ 20। वैकल्पिक: स्थापित-मॉडल कैटलॉग के लिए [ओलामा](https://ollama.com), और उत्पन्न कमांड चलाने के लिए लामा.cpp / एलएम स्टूडियो। आरटीएक्स 5090 पर लाइव परीक्षण किया गया।

## सुरक्षा

कोई टेलीमेट्री नहीं। डिफ़ॉल्ट रूप से कोई बाहरी नेटवर्क नहीं — कैटलॉग स्थानीय ओलामा लूपबैक एपीआई का उपयोग करता है; वैकल्पिक `--hf` ध्वज huggingface.co से सार्वजनिक जीजीयूएफ हेडर प्राप्त करता है (डिफ़ॉल्ट रूप से बंद, केवल-पढ़ने के लिए, भार कभी भी डाउनलोड नहीं किया जाता है)। स्थानीय मॉडल फ़ाइलों और सिस्टम जानकारी पढ़ता है, और विश्वसनीय सिस्टम बाइनरी (`nvidia-smi`) पर शेल करता है। अविश्वसनीय जीजीयूएफ हेडर की सीमा-जांच की जाती है। [SECURITY.md](SECURITY.md) देखें।
